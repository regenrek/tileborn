# Design System

## Principles

Calm, non-blocking, explicit status. Never imply rollback or data loss.

## Components

Reuse existing settings rows, buttons, progress/status presentation, toast or
notification surfaces, and confirmation dialogs. Do not add a parallel shell.

## Accessibility

Keyboard-operable actions, visible focus, semantic live status for progress and
completion, reduced-motion-compatible feedback, and readable error text.
